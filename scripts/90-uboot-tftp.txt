U-Boot 里用 TFTP 升级 bootloader / 引导 initramfs（不用按 reset、不用 U 盘）
============================================================================

什么时候能用 TFTP
----------------
  首次（刚从 diagnostic mode 写完 mtd0）必须走 U 盘：插 U 盘冷启动一次，
  把 initramfs 拉起来。之后这台机器才能靠 TFTP 救砖。

  原因不在硬件，在 U-Boot 自己的三个行为：
    1) 环境变量从 NAND（0x440000）读，读到的合法环境会整份取代编译内置默认值，
       不是逐项合并。老版本 u-boot-env 或残留的原厂环境会让 enable_tftp_boot /
       tftp_boot 这些变量缺失。
    2) tftp_checkboot 以前写成 `if test $enable_tftp_boot = 1`：变量缺失时 hush
       把空参数丢掉，test 只剩 2 个参数，do_test() 判定为假 —— 这一步被静默跳过，
       屏幕上什么都不报。
    3) tftp_boot 里 setenv netretry no 等价于 retrycnt=0，第一次失败就整轮放弃；
       而且这块板的驱动不做真实链路检测（bcmiproc_robo.c 直接把端口强制标成 link up），
       链路没通只会表现为 ARP 超时，不报错。

  v6 起 (2) 改成 `test "x${enable_tftp_boot}" != "x0"`，变量缺失也是启用。

前提：已经刷上本项目编译的 U-Boot（mx64-ng-2012.10-v5 或更新，带 flash_uboot 命令）。
      PC 网卡与设备同网段（下面按惯例用 192.168.1.2/24），TFTP 服务器跑在 PC 的 IP:69
      （kit 里：python scripts\70-tftp-server.py；Windows 不需要管理员，Linux 需要 root）。


0) 上电后 3 秒内按任意键，停在 U-Boot 提示符（CONFIG_BOOTDELAY=3）

   如果不按键，U-Boot 会按 UBI -> USB -> TFTP -> meraki 的顺序自动尝试。
   默认 enable_usb_boot=1、enable_tftp_boot=1：NAND 空/坏时先找 U 盘，
   没有 U 盘就自己从网络拉镜像，都不需要按 reset。


1) 看设备状态

   mx64info
   nand info

   mx64info 里重点看:
     SoC      : B0+ / A0            <- 决定用哪个 initramfs
     dts cfg  : config@4 / config@2
     loadaddr : 90000000


2) 设置网络（只需一次，saveenv 之后就不用再设）

   setenv ethaddr 00:18:0a:00:01:02        <- 换成你机器标签上的 MAC
   setenv ipaddr 192.168.1.10              <- 同网段任意空闲地址
   setenv serverip 192.168.1.2             <- 换成 PC 的 IP
   setenv netmask 255.255.255.0
   ping 192.168.1.2
   saveenv


3) 用 TFTP 引导 initramfs / 过渡固件（不按 reset）

   tftp_boot

   它会按顺序试三个文件名，第一个能加载的就引导：
     1. ${tftp_file}                     (你手动设的，可选)
     2. openwrt-bcm53xx-generic-meraki_mx64[-a0]-initramfs.bin         <- 正常路径用这个
     3. openwrt-bcm5862x-generic-meraki_mx64[a0]-initramfs-kernel.bin  <- 只有 512 KiB 机器才用

   两个文件是不同容器，不是同一东西的两个版本:
     FIT  (d0 0d fe ed) = OpenWrt RAM 系统，bootm 引导，装完 sysupgrade 就好了
     SPIM (53 50 49 4d) = Meraki loader 格式的过渡固件，bootbk 引导，
                          里面带 1 MiB 版 uboot_mx64，只为把 512 KiB 分区换成 1 MiB

   A0/B0+ 的名字由 config_dts 自动选。每个文件都交给 bootimg 判断类型:
     d0 0d fe ed (FIT)  -> bootm <addr>#<config@N>
     53 50 49 4d (SPIM) -> 搬到 0x60008000 后走 bootbk

   TFTP 根目录直接放 kit 的 files/ 内容即可，不用改名。

   想只刷一个固定文件（正常路径就写 FIT 那个名字）:
     setenv tftp_file openwrt-bcm53xx-generic-meraki_mx64-initramfs.bin
     tftp_boot

   想手动指定地址:
     tftpboot 0x90000000 openwrt-bcm5862x-generic-meraki_mx64-initramfs-kernel.bin
     bootimg 0x90000000 bootkernel1


4) 用 TFTP 直接重写 bootloader（flash_uboot）

   flash_uboot uboot_ng.bin 100000 confirm

   参数:
     uboot_ng.bin   TFTP 服务器上的文件名
     100000         mtd0 的真实大小，十六进制。512 KiB 的机器写 80000
                    （拿不准就先在 OpenWrt 里 cat /proc/mtd）
     confirm        必须写，否则命令拒绝执行

   它会做:
     1. tftpboot 到 ${loadaddr}
     2. 检查首字是不是 ARM 跳转指令、长度是否 <= 分区大小
     3. nand erase 0 <分区大小>
     4. nand write ${loadaddr} 0 <文件长度>
     5. nand read 到 ${verifyaddr}，CRC32 比对
     6. 只有比对通过才打印 OK

   中途断电 = 变砖，必须接串口救。所以：
     - 别在没接串口的时候刷
     - 别用 80000 的机器刷 596 KB 的镜像（会被拒绝）
     - 校验失败就再跑一次，不要直接 reset


5) 512 KiB 分区（mtd0 = 0x80000）的机器

   596 KB 的 uboot_ng.bin 放不进去。先用 clayface 的 uboot_mx64_small 起步，
   再用过渡固件（openwrt-bcm5862x-...initramfs-kernel.bin）从 U 盘/TFTP 引导，
   在里面执行：

     mtd write /root/uboot_mx64 /dev/mtd0

   换成 1 MiB 布局之后，就能用 flash_uboot 刷 uboot_ng.bin 了。


6) 救砖（U-Boot 还能起来但 NAND 是空的）

   什么都不用按：
     - 插着带 initramfs 的 U 盘 -> 自动 usbload
     - 没 U 盘但有 TFTP 服务器 -> 自动 tftp_boot
     - 想跳过 UBI 引导直接进恢复: setenv disable_ubi_boot 1


7) 常用排错

   TFTP 完全没反应
                    -> 先在 U-Boot 提示符敲 printenv，看 enable_tftp_boot / tftp_boot
                       在不在。缺变量说明 NAND 里的 u-boot-env 比二进制老：
                         setenv enable_tftp_boot 1
                         saveenv                       （不碰 mtd0，没有变砖风险）
                       或者用 tools/mkenv.py 重新生成 uboot-env.bin 写到 mtd3。
                     -> 再看 ping 192.168.1.2 通不通（ARP 通不通）：
                         ping 不通 -> 交换机/GMAC 这一侧，网线、PC 防火墙、gmac 变量
                         ping 通但 tftpboot 失败 -> PC 上的服务端/文件名/块大小

   ping 不通          -> 网线是不是插在 LAN 口、PC 防火墙、ipaddr/serverip 是不是对
   TFTP timeout       -> PC 上 TFTP 服务器没起，或 UDP 69 被别的进程占用 / 被防火墙拦
   Bad Bootkernel magic / No FIT/uImage/SPIM magic
                      -> 文件不对或没传完整，重新传
   VERIFY FAILED      -> NAND 写坏了，重新跑 flash_uboot；反复失败就别再刷
